01十分钟上手

万卷阁是一个运行在本机的离线阅读程序。它不需要注册，不会把你的书、笔记或密钥上传到任何服务器；断网时，除“在线翻译”外的所有功能都能正常使用。

书库共 6,355 章、14 个分类，全部随发行包离线提供；五个平台启动路径（Windows、Linux、macOS、Android Termux、iPhone/iPad iSH）共用同一套源码。

这个程序适合谁

适合

  • 想在没有网络的飞机、地铁、山区或隔离电脑上读典籍的人。
  • 希望原文、笔记、密钥都留在自己机器上，不接受账号与云同步的人。
  • 需要把古文逐段对照现代汉语或英文，但不满意网页机翻排版的人。
  • 带学生或自学语文、数学、英语、科学、计算机、驾考，想要“读完一章立刻做题”的人。
  • 愿意自己维护一台电脑、一个 Node.js 运行时，换来确定与可控的人。

不适合

  • 想要“下载即用、完全不需要命令行”的纯桌面软件用户。这里是本机网页应用。
  • 需要多用户、权限、审计、云同步的机构场景。本项目没有账号系统。
  • 需要权威点校本、学术注释、版权译本的读者。书库以白文与原创导读为主。
  • 想用它替代考试机构判卷的人。习题与 AI 批改只是学习辅助。
  • 需要手机原生 App 安装包的人。本项目提供 PWA 与 WebView 外壳工程，不附带签名 APK/IPA。

三种使用方式：先选一种

方式怎么用优点代价 / 限制
A. 本机桌面（推荐）在 Windows / Linux / macOS 安装 Node.js 18+，解压发行包，双击启动器，浏览器访问 http://127.0.0.1:7410速度最快；数据只在本机；可装成 PWA；适合长篇与整本翻译需要安装 Node.js；关机或关闭服务窗口后不可访问
B. 手机本机Android 用 Termux 跑同一套 Node 服务；iPhone/iPad 用 iSH 跑服务，再用本机浏览器打开完全离线；数据留在手机；可添加到主屏幕安装步骤多；低端机打开超大书较慢；后台可能被系统回收
C. 电脑服务 + 手机阅读电脑以 WANJUAN_HOST=0.0.0.0 启动，手机浏览器访问 http://电脑IP:7410手机不承担 Node 开销，翻页与搜索最快；电脑统一保存数据需要同一 Wi-Fi；局域网模式无登录，只应在可信网络临时开启

第一次打开后，按这个顺序体验

  1. 看首页统计。确认“171 部 / 1962.6 万字 / 14 个分类”三项出现，说明目录与书库加载正常。
  2. 点“按分类浏览”。先看“学术”与“文化”两类，确认 23 部新书已经在架；再回书架。
  3. 打开一本有习题的书。例如《万卷阁全科自测习题集》第 2 章，滚到正文末尾，做一道选择题，确认即时判分与解析。
  4. 试一次搜索。在顶部输入 上善若水，应出现《道德经》等多条命中；点结果跳到对应章节。
  5. 加一个书签与一条笔记。在阅读页点 ☆ 与 ✎，然后到顶部“书签”“笔记”两页确认出现；这两项写入本机 data/user.json。
  6. （可选）配置翻译接口。到“设置”填 Base URL、模型与 API Key，点“测试连接”；成功后回到阅读页点“译本章”。不配置也不影响任何离线功能。
  7. （可选）安装 PWA。在 Chrome/Edge 地址栏点安装图标，或 Safari 选择“添加到程序坞/主屏幕”。
  8. （可选）导入一本自己的书。到“导入”粘贴纯文本或选择 .txt/.md，确认生成新书并可搜索、加书签。
最短路径：只想先读一本书，可以只做“安装 Node.js → 解压 → 双击启动器”三件事；其余功能都可以以后再加。程序不会在后台自动联网，也不会因为你没有配置接口而减少离线功能。

Windows：四步开始

  1. 安装 Node.js。到 nodejs.org 下载 LTS 安装包，安装时勾选 “Add to PATH”，然后在命令行用 node -v 确认版本不低于 18。
  2. 解压下载的 wanjuan-ge-v1.1.1-windows.zip 到任意目录。建议放在 D:\万卷阁 这类不含权限限制的位置，不要放在 C:\Program Files。
  3. 双击launchers\windows\万卷阁.bat。会弹出一个命令行窗口，显示 Node 版本与服务地址 http://127.0.0.1:7410，并另开“万卷阁 服务端”窗口运行服务。这个服务端窗口就是服务器，关掉它程序就停止。
  4. 浏览器会在 1 秒后自动打开书架。若没有自动打开，手动访问 http://127.0.0.1:7410。第一次进入后，点地址栏右侧的“安装”图标，可把万卷阁装成桌面应用。
运行方式：发行包不附带 Node 运行时，Windows / Linux / macOS / Termux / iSH 都需要本机安装 Node.js 18+。程序零第三方依赖，不需要 npm install。想后台静默运行，可双击 万卷阁-无窗口.vbs，停止时在任务管理器结束 node.exe。若杀毒软件拦截，请把程序目录加入信任；程序只监听本机回环地址，不对外开放。

02五个平台安装详解

五个启动器共用同一套 server.js、lib/、public/ 与 library/。差别只在“由谁提供 Node 运行时”和“用什么脚本启动”。

2.1 Windows 10 / 11（需 Node.js 18+）

  • 发行包：wanjuan-ge-v1.1.1-windows.zip，包含完整运行文件与 launchers/windows/。
  • 安装 Node.js LTS 后，双击 万卷阁.bat：它会检查 Node、进入项目根目录、启动 server.js，等待 1 秒后用默认浏览器打开 http://127.0.0.1:7410，并保留控制台便于查看日志。
  • 万卷阁-无窗口.vbs 会在后台静默启动并打开浏览器；停止时在任务管理器结束 node.exe。需要排错时请改用 .bat。
  • 首次启动如果弹出 Windows 防火墙提示，请选择“取消”或“不允许”。程序只监听 127.0.0.1，不需要放行公网。
  • 不要同时启动两个副本，否则第二个会因端口占用自动改用 7411、7412……日志里会写明实际地址，启动器也会提示查看控制台。
  • zip 解压不会改变批处理/脚本的可用性；若路径含中文或空格，启动器已用引号处理，仍建议解压到较短路径。

2.2 Linux（x64 / ARM64）

  1. 安装 Node.js 18+。Debian/Ubuntu：sudo apt install nodejs；Fedora：sudo dnf install nodejs；Arch：sudo pacman -S nodejs；或使用 nvm 安装当前 LTS。用 node -v 确认版本。
  2. 解压发行包：tar -xzf wanjuan-ge-v1.1.1-linux.tar.gz，进入 wanjuan-ge-v1.1.1-linux/。
  3. 启动：chmod +x launchers/linux/wanjuan-ge.sh && ./launchers/linux/wanjuan-ge.sh。脚本会检查 Node 版本，启动服务器，等待 1 秒后用 xdg-open 打开浏览器。
  4. 后台运行（可选）：nohup node server.js > data/server.log 2>&1 &。停止时用 pkill -f "node server.js"，或按记录的 PID 结束。

ARM64 Linux（树莓派、部分云主机）同样可用；如果发行包架构不匹配，直接复制源码目录并在本机执行 node server.js 即可，程序没有原生依赖。zip 解压可能丢失执行位，tar.gz 包已保留 755；若提示 Permission denied，补一次 chmod +x。

2.3 macOS 11+

  1. 安装 Node.js：从 nodejs.org 下载安装包，或 brew install node。确认 node -v 不低于 18。
  2. 解压发行包，双击 launchers/macos/万卷阁.command。若系统提示“无法验证开发者”，在 Finder 中右键该文件，选择“打开”，再确认一次。
  3. 终端会显示启动地址，Safari 会自动打开。以后可以把 万卷阁.command 拖到程序坞或设置为登录项。
  4. 若双击无反应或提示权限不足，在终端执行 chmod +x launchers/macos/万卷阁.command；也可用 xattr -d com.apple.quarantine 清除隔离标记。
Apple 芯片与 Intel 通用：程序是纯 JavaScript，没有编译产物，因此同一个包在 M 系列与 Intel Mac 上都能运行，只要本机 Node 架构正确。

2.4 Android：Termux + PWA（推荐）

Android 上没有随仓库提供的 APK，但 Termux 提供一个完整的 Linux 用户态，可以在手机上直接跑 Node 服务；再用 Chrome 把页面“添加到主屏幕”，体验接近原生应用。

  1. 安装 Termux：从 F-Droid 或 Termux 官方 GitHub Releases 安装（不要用早已停更的 Play 商店旧版）。
  2. 准备文件：把 wanjuan-ge-v1.1.1-android-termux.zip 传到手机并解压，进入 launchers/android-termux/；先执行 termux-setup-storage 授权访问下载目录。
  3. 安装：bash install.sh。脚本执行 pkg update、pkg install nodejs git，把项目复制到 ~/wanjuan-ge，启动服务并用 termux-open-url 打开 Chrome。本项目零依赖，不需要 npm install。
  4. 日常启动：bash ~/wanjuan-ge/launchers/android-termux/start.sh。脚本会申请唤醒锁、启动服务并打开 http://127.0.0.1:7410。
  5. 装到桌面：Chrome 菜单 →“添加到主屏幕”/“安装应用”。之后从桌面图标进入，全屏阅读。
手机性能与耗电：首次打开《资治通鉴》这类超大书或圣经 JSON 时，低端机可能需要几秒。Termux 被系统杀后台时服务会停止，重新运行 start.sh 即可，阅读数据不会丢失；可在 Termux 通知栏选择“Acquire wakelock”，并关闭对 Termux 的电池优化。

2.5 iPhone / iPad：iSH + PWA

iSH 是一个在 iOS 上运行的 x86 Linux 模拟器，可以从 App Store 免费安装。它能运行 Node.js，但性能弱于桌面，且 Alpine 源的 Node 版本可能较旧；适合查阅与短篇阅读，不建议在旧设备上一次性打开超大长篇。

  1. 安装 iSH，打开后确认能执行 apk --version。
  2. 导入文件：通过“文件”App 把 wanjuan-ge-v1.1.1-iphone-ipad-ish.zip 放到 iSH 可访问的位置并解压。
  3. 安装并启动：cd launchers/iphone-ipad-ish && sh install.sh。脚本执行 apk add nodejs，把项目复制到 ~/wanjuan-ge，然后调用 start.sh 前台运行服务，并打印 Safari 访问地址。首次启动较慢，请保持 iSH 在前台；以后启动只需 sh ~/wanjuan-ge/launchers/iphone-ipad-ish/start.sh。
  4. 阅读：iSH 内不能自动唤起浏览器，请手动切到 Safari 打开 http://127.0.0.1:7410，点分享按钮 →“添加到主屏幕”。
更流畅的替代方案：把书库放在家里的电脑上运行（见 2.7 局域网访问），iPhone 只用 Safari 访问电脑地址。这样手机不承担 Node 运行开销，翻页与搜索都更快。若 node -v 低于 18，可先 apk update && apk add nodejs 升级；仍不满足时请改用局域网方案。

2.6 安装为 PWA（Windows / macOS / Linux / Android）

  • Chrome / Edge：地址栏右侧出现安装图标时点击；或菜单 →“安装万卷阁”。
  • 安装后拥有独立窗口、桌面图标与离线壳缓存。即使服务器暂时没开，已缓存的界面仍能打开，但正文接口需要服务运行。
  • Safari（macOS）：文件 →“添加到程序坞”。iOS/iPadOS Safari：分享 →“添加到主屏幕”。
  • 说明：完整 PWA 安装提示通常要求 HTTPS 或 localhost。通过 http://局域网IP 访问时，Chrome 一般只创建快捷方式；在手机本机用 http://127.0.0.1:7410 属于安全上下文，体验更接近原生。

2.7 局域网访问（可选，默认关闭）

默认只监听 127.0.0.1，同一 Wi-Fi 下的其他设备无法访问。若想让平板或手机读取电脑上的书库，可在启动前设置环境变量：

  • Windows CMD：set WANJUAN_HOST=0.0.0.0 && node server.js
  • Linux / macOS：WANJUAN_HOST=0.0.0.0 node server.js
  • 然后在手机浏览器访问 http://电脑的局域网IP:7410，或把该地址填入 Android WebView 外壳的“服务器地址”。
安全提醒：程序没有登录系统。改成 0.0.0.0 后，同一网络中的任何人都能读取你的书库与笔记。只在可信的家庭网络中临时开启，用完改回默认值。

2.8 端口、停止与卸载

  • 默认端口 7410；被占用时自动尝试 7411–7430，实际地址以日志为准。也可用 WANJUAN_PORT=8080 指定。
  • 停止：关闭启动窗口/终端（Windows 无窗口模式在任务管理器结束 node.exe），或结束 node server.js 进程。
  • 卸载：删除整个程序目录即可。书签、笔记、译文缓存都在目录内的 data/，删目录前请先备份 data/ 与 library/books/（如果你导入过自己的书）。

2.10 开机自启动：三种系统的做法

万卷阁本身不写注册表、不装服务，是否开机自启由你决定。以下做法都需要先确认 node server.js 能在项目根目录正常启动；自启动只是把这条命令交给系统。

系统做法停止 / 卸载
Windows任务计划程序 → 创建任务 → 触发器“登录时” → 操作“启动程序”：程序填 node.exe 的完整路径，参数填 server.js，起始于填项目目录；勾选“不管用户是否登录都要运行”可按需选择在任务计划程序中禁用或删除任务；不需要卸载程序
Linux（systemd 用户服务）新建 ~/.config/systemd/user/wanjuan-ge.service，ExecStart=/usr/bin/node /home/你/wanjuan-ge/server.js，WorkingDirectory=/home/你/wanjuan-ge，然后 systemctl --user enable --now wanjuan-gesystemctl --user disable --now wanjuan-ge，再删除 unit 文件
macOS（launchd 登录项）系统设置 → 通用 → 登录项，把 万卷阁.command 加入；或在“终端”中运行一次启动脚本并保持窗口从登录项移除；结束 node 进程

2.11 升级、回滚与保留数据

  • 升级前：停止服务，备份 data/ 与 library/books/。内置书会随新发行包更新，导入书与用户数据不会自动合并。
  • 升级：把新发行包解压到新目录，再把旧的 data/ 与 library/books/ 复制过去；确认新版本能启动后，旧目录可保留一段时间再删除。
  • 回滚：保留上一版程序目录与升级前的 data/ 备份；回滚时先停服务，再用旧目录启动。不要在新旧两个目录之间同时运行服务，否则会争用同一个端口与同一份用户数据。
  • 缓存：data/search-index.json 与 data/translations/ 都可以删除重建；data/user.json 不可删除，否则设置、进度、书签、笔记与密钥都会清空。

4.4 失传与真伪：本程序的态度

《连山易》《归藏易》在汉代以后即已散佚，今日所见只有辑佚与转引。本程序不伪造“全文”，而是提供各 10 章的存佚考导读，交代文献线索、辑佚来源与学术争议；《奇门遁甲》以导读与考据呈现；《烧饼歌》《乾坤万年歌》《格庵遗录》均收录通行本全文并附解说与考辨；《赫尔墨斯文书》《古埃及预言》《波斯圣书·阿维斯陀》依据公有领域译本全文译述。引用原文时均注明出处，不把后世托名之作冒充原典。

05在线翻译：把整章或整本书译成现代汉语或英文

翻译是可选功能。程序本身不带模型，也不代付费用；你填入自己的 OpenAI 兼容接口，翻译请求从本机直接发往该接口，不经过万卷阁的任何中间服务器。

5.2 配置步骤

  1. 打开「设置」，在“在线翻译接口”里选择预设：DeepSeek、通义千问、OpenAI、Ollama。预设只填 Base URL 与模型名，密钥仍需你自己提供。
  2. 填入 API Key。保存后页面只显示掩码（如 ••••3f9a），再次编辑时留空表示不修改。
  3. 点“测试连接”。程序会发送一条极短的测试消息，成功后显示模型返回的内容；失败会给出 HTTP 状态或网络错误。
  4. 回到阅读页，点“译本章”翻译当前章，或点“译全书”从当前章开始逐章翻译整本。首次翻译会逐批请求，按钮显示进度；完成后正文下方出现译文块。
  5. 切换目标语言：阅读页标题旁的“现代汉语 / English”下拉框。切换后重新点“译本章”，程序会按语言分别缓存，不会覆盖。

5.4 费用、速度与质量控制

  • 批量：每批最多 10 段、3,200 字；超长章会自动分成多批。每批要求模型返回严格 JSON 数组，段数不符即判定失败并重试一次。
  • 缓存：译文按“书 + 语言”写入 data/translations/，同一章第二次打开不再请求。删除该目录即可全部重译。
  • 费用估算：以百万字全库粗略估算，使用低价中文模型大约几元到几十元人民币；实际取决于模型单价、重复翻译次数与上下文长度。此处只是量级估计，不是报价。
  • 质量：机器翻译适合“读懂大意”，不适合替代学术译注。古文中的通假、名物、职官、避讳，模型可能误译；涉及法律、医疗、宗教教义时请以权威译本为准。
  • 断网：未配置接口或网络不通时，点“译本章”或“译全书”会提示错误，原文照常显示，不会卡住界面。

5.5 译全书：一次翻完整本

阅读页标题栏的“译全书”按钮用于整本连续翻译，适合长篇典籍与圣经各卷。它的行为与“译本章”一致，只是把范围扩展到全书，并且在翻译过程中允许随时停止。

  1. 确认范围：点击后先弹出确认框，显示本书总章数与当前目标语言。整本翻译会消耗大量 token，确认框会明确提示这一点。
  2. 逐章执行：程序从当前章开始，按章循环调用同一套翻译接口；每章仍按“每批 ≤10 段 / 3,200 字”切分，并校验返回段数。
  3. 缓存复用：已翻译过的章节直接读取 data/translations/，不会重复计费；中途停止后再次点击，会从第一章起跳过已有缓存，继续未完成部分。
  4. 随时停止：翻译期间按钮切换为“停止”。点击后不再发起新请求，已完成的章节照常保留；当前正在请求的一章完成后停止，不会写坏缓存。
  5. 进度与失败：页面显示“已完成 / 总数 / 失败章数”。单章失败不会中断整本流程，程序会记录失败并在结束时汇总，可稍后重试补齐。
  6. 阅读不受影响：翻译在后台逐章进行，你可以继续滚动阅读当前章；译文完成后自动替换为对照视图。
整本翻译的成本提醒：以百万字级书籍为例，整本机译可能产生数十万至数百万输入 token。请先在“译本章”上测试模型质量与单价，再决定是否整本翻译；对超长书（如《华严经》《史记》）建议按需选章，而不是一次全译。程序不代付任何费用，也不会在未经你点击的情况下自动发起请求。
密钥安全：API Key 只写入本机 data/user.json，接口返回时始终掩码，日志不记录请求头。请不要把 data/user.json 发给别人，也不要把带密钥的截图上传。怀疑泄露时，在服务商后台吊销并重新生成。

5.6 习题自测与 AI 批改

语文、数学、英语、科学、计算机、驾考、文化与诗词曲书籍均配有章末习题，全书库合计 702 道。打开任意一章，正文之后会自动出现“本章习题”面板。

  • 客观题：选择、判断、填空题提交后在本机判分。答对显示绿色提示，答错显示正确答案与解析；填空题有多个空时，按“；”分隔逐空比较。
  • 主观题：先在文本框作答，可点“查看参考要点”自行对照；配置好接口后，点“AI 批改”会返回百分制评分、等级、优点、可改进之处与学习建议。
  • 自动保存：作答与判分结果按“书 + 章”保存在浏览器 localStorage，刷新页面、切换译文都不会丢失；清除浏览器站点数据会清空。
  • 隐私边界：AI 批改只发送当前题目、参考要点与你的答案，不发送其他章节、笔记或书签；密钥留在服务端本机配置文件，不会下发到浏览器。
  • 结果定位：自动评分是学习辅助，不是考试判卷。主观题只要论述合理即可，评分与建议仅供参考。
未配置接口也能用：客观题判分、解析与主观题参考要点完全离线；只有“AI 批改”需要你在 5.2 节配置的 OpenAI 兼容接口。

07进度、书签与笔记

所有阅读数据只存在本机 data/user.json，不上传、不合并、不做任何统计。

  • 阅读进度：每次翻章自动记录“书 + 章 + 百分比 + 时间”。书架顶部的“继续阅读”会跳到上次位置。
  • 书签：阅读页点 ☆，可写一句备注；书签页按时间倒序列出，点击回到原章。
  • 笔记：点 ✎ 写下想法，笔记页支持编辑与删除；笔记与书、章绑定，但不会自动引用原文，建议自己摘一句作为线索。
  • 备份：退出程序后复制整个 data/ 目录即可。恢复时把它放回程序目录。若只想迁移阅读数据，复制 data/user.json 即可；译文缓存很大，可按需复制 data/translations/。
  • 清理：删除 data/user.json 会清空进度、书签、笔记与设置（包括密钥）；删除 data/translations/ 只清译文缓存。
多设备：v1.1.1 不做云同步。想在手机与电脑之间共享，可把书库放在电脑上并临时开启局域网访问（2.7），或在两台设备间手动复制 data/。不要使用网盘实时同步正在运行的用户文件，避免写冲突。

08导入自己的书

内置书库只是起点。任何你有权使用的纯文本，都可以导入成与内置书同权的书籍：可搜索、可翻译、可加书签、可导出 JSON。

8.1 通过界面导入

  1. 打开“导入”，填写书名（必填）、作者/译者、时代、分类、标签与导读。
  2. 粘贴正文，或选择 .txt / .md 文件（≤ 48 MB，只在本机读取）。
  3. 点“导入并阅读”。程序按章节标题或空行切分，生成 library/books/import-*.json，随后跳转到新书详情页。

8.2 章节如何切分

  • 优先识别：第X章、第X回、第X卷、卷X、第X节，以及“纪/传/志/表/书/训/篇/经/品 + 第X”等古典标题。
  • 若全文没有标题，按空行分段，并把整篇作为一章（可通过“默认章节标题”命名）。
  • 过短的段落会与相邻段合并，避免出现一句一段的碎片；过长的段落会按句末标点拆分，保证翻译批次稳定。
  • 繁体文本可在导入时勾选“转换为简体”（若界面提供该选项）；程序内置 OpenCC 常用字表，转换只影响显示，不改源文件。

9.7 圣经正典结构

和合本 66 卷分为旧约 39 卷与新约 27 卷。旧约按摩西五经、历史书、诗歌智慧书、大先知、小先知分组；新约按福音书、使徒行传、保罗书信、普通书信、启示录分组。阅读页的目录也按这个结构展开。

9.8 佛道经典结构

关于“所有经文咒语”：佛教《大正藏》有 3,000 余部、道教《道藏》有 1,476 种，全部数字化文本体量以 GB 计，且不同版本、校勘与仪轨差异极大。v1.1.1 选择各传统最核心、最常诵读的 33 部（释 16 + 道 17），保证每一部都能完整阅读与翻译；需要更多文本时，可按第 08 章导入 CBETA 或 Kanripo 的对应文本。把“所有”如实拆成“核心全集 + 可持续扩充”，比用删节本冒充全藏更负责任。

10常见问题

启动与访问

问：双击后窗口一闪而过。
答：用 launchers\windows\万卷阁.bat（不是 .vbs）启动，查看报错。常见原因是未安装 Node.js、Node 不在 PATH、目录被解压到受保护位置，或 7410–7430 端口都被占用。先执行 node -v，再换目录或设置 WANJUAN_PORT 重试。

问：浏览器打开是空白页。
答：确认地址是 http://127.0.0.1:7410，不要用 https，也不要直接双击 index.html（file:// 下接口不可用）。按 F12 看 Console 是否有 404；若是旧缓存，按 Ctrl+F5 强制刷新。

问：端口 7410 被占用怎么办？
答：程序会自动尝试 7411–7430，日志里会打印实际端口。也可以 WANJUAN_PORT=8080 node server.js 指定。Windows 查看占用：netstat -ano | findstr :7410。

问：能不能不装 Node？
答：不能。所有平台的发行包都不附带 Node 运行时，需本机安装 Node.js 18+（Termux / iSH 由脚本用包管理器安装）。程序零第三方依赖，不需要 npm install；若发行包架构不符，复制源码目录并在本机装 Node 即可。

阅读与文本

问：为什么《史记》只有 15 章？
答：v1.1.1 的 Kanripo 源文件把史记拆成 14 个超大卷文件，缺少篇级标题，程序按文件切分，因此只有 15 章。正文并未删减，约 70.9 万字。后续版本会按“本纪/表/书/世家/列传”重建篇级目录。

问：为什么有的书是繁体？
答：汉籍以 Kanripo 繁体白文为底本，保留原字；圣经已统一转为简体。你可以在导入时转换，或后续版本增加“全书简繁切换”。

问：注释、白话、译文为什么没有？
答：现代注释与译本有版权，不能内置。程序提供“在线翻译”作为可选的机器译文，并明确标注其局限；需要权威注本时请自行导入合法文本。

问：连山易、归藏易为什么不是全文？
答：两书在汉代以后已散佚，现存只有辑佚与转引。程序不伪造全文，而以“存佚考”交代文献与争议。详见第 04 章。

问：圣经真的没有删减吗？
答：内置和合本 66 卷、1,189 章、31,104 节，逐节完整；程序在导入时校验了卷数、章数与节数，任何一项不符都会拒绝生成。次经不在新教正典内，故未混入，详见 4.2。

翻译

问：点“译本章”提示未配置密钥。
答：到“设置”填入 Base URL、模型与 API Key，先点“测试连接”。Ollama 本地接口可留空密钥，但需要本机已运行 Ollama 并拉取模型。

问：翻译到一半失败。
答：多为网络超时、额度不足或模型返回的段数不符。程序保留已成功批次的缓存，重试会从缓存继续；若持续失败，换模型或降低批量（后续版本提供）。翻译失败不会影响原文。

问：译文会不会上传我的书？
答：只有你点击“译本章”时，当前章的段落才会发往你配置的接口；其余书籍、笔记、书签不会发送。接口方的数据政策由其自身决定，请阅读其条款。

数据与备份

问：换电脑怎么迁移？
答：复制整个程序目录，或至少复制 library/books/（含导入书）、data/user.json（进度/书签/笔记/设置）与 data/translations/（译文缓存）。新机器上启动即可。

问：导入的书在哪里？
答：library/books/import-*.json。想导出单本，可用书籍详情页的下载按钮（若有）或直接复制该 JSON；也可访问 /api/books/<id>/download。

问：删除内置书会怎样？
答：内置书受保护，接口会拒绝删除。要精简书库，可在停止程序后手动移动 library/books/ 中对应 JSON，并删除 library/catalog.json 让程序重建目录。

平台

问：为什么没有 APK / IPA？
答：构建 APK 需要 Android SDK、Gradle 与你自己的 keystore，构建 IPA 需要 macOS、Xcode 与开发者证书，本程序的构建环境不具备这些工具链，仓库也不会伪造或附带安装包。android/ 目录提供可导入 Android Studio 的 WebView 工程骨架，需你自行改地址、Build APK 并用自有 keystore 签名。日常使用推荐 Termux/iSH 运行同一套 Node 代码，再“添加到主屏幕”，功能与桌面版一致。

问：iPhone 上 iSH 很慢。
答：iSH 是模拟器，性能有限。优先用“电脑跑服务 + 手机 Safari 局域网访问”（2.7），或只读短篇。旧设备不建议打开《资治通鉴》这类超大书。

问：PWA 离线能读吗？
答：PWA 壳与静态资源可离线缓存，但正文通过本机接口读取，因此仍需 Node 服务运行。真正的“完全离线”由桌面/ Termux/iSH 的本地服务保证。

12隐私与安全

  • 只监听本机：默认绑定 127.0.0.1，局域网与公网都无法访问。除非你主动设置 WANJUAN_HOST=0.0.0.0。
  • 无账号、无遥测：程序不收集设备信息、阅读行为或崩溃日志，不包含任何统计脚本、广告或第三方字体。
  • 密钥本机保存：API Key 存在 data/user.json，接口响应始终掩码；请像保护密码一样保护该文件。
  • 安全头：服务设置了 CSP、X-Content-Type-Options、X-Frame-Options 与 Referrer-Policy，前端不使用 eval 或远程脚本。
  • 在线接口外发边界：只有你点击“译本章”“译全书”或主观题“AI 批改”时，当前章正文或该题答案才会发往你配置的接口；书目、笔记、书签、其他作答与密钥不会随请求发送（密钥仅用于 Authorization 头）。
  • 局域网风险：开启 0.0.0.0 后没有登录与权限控制，任何能访问该端口的人都能读写你的书库数据（接口含删除/导入）。只在可信网络临时使用。
  • 导入文件：只接受文本，不执行其中的脚本；但请勿导入来源不明的超大文件，避免占满磁盘。
没有“云同步”不是缺陷：这意味着没有中心服务器可被拖库，也没有账号可被撞库。代价是换设备要手动迁移。对典籍与私人笔记来说，这个取舍是故意的。

B附录 B：HTTP API 参考

万卷阁的所有界面都建立在同一组本地 HTTP 接口上。接口没有鉴权、没有 Cookie、不依赖数据库；默认只监听 127.0.0.1，请求与响应均为 UTF-8 JSON（书籍下载与静态文件除外）。你可以用 curl、PowerShell、Python 或自己的脚本读取书库、同步进度、批量导出笔记。

B.1 通用约定

  • 基地址：http://127.0.0.1:7410。若改了端口或监听地址，请相应替换。
  • 请求体：Content-Type: application/json，最大 2MB；超限返回 413。
  • 成功响应：HTTP 200 + JSON；失败响应：HTTP 4xx/5xx + {"error":"中文错误说明"}。
  • 没有认证头。不要在公网直接暴露端口；需要远程访问时用 SSH 隧道或反向代理加认证。
  • 除 /api/search 的 limit 外，所有数值参数都会做上下限截断，不会因为传入负数或超大值而崩溃。

C.3 章节与四种习题

章节对象只有三个常用字段：title（章节标题）、paragraphs（段落字符串数组，阅读页逐段渲染）、exercises（可选的习题数组）。习题支持四种类型，字段如下：

// 1) 单项选择题：answer 是选项字母，options 必须带“A. ”前缀
{
  "type": "choice",
  "q": "用0、1、2、3组成没有重复数字的三位数，共有多少个？",
  "options": ["A. 12个", "B. 18个", "C. 24个", "D. 27个"],
  "answer": "B",
  "explain": "百位3种（不能为0），十位3种，个位2种：3×3×2＝18。"
}

// 2) 判断题：answer 是布尔值，不是字符串
{
  "type": "judge",
  "q": "任意两个大于2的质数之和一定是偶数。",
  "answer": true,
  "explain": "大于2的质数都是奇数，奇＋奇＝偶。"
}

// 3) 填空题：多个空用全角分号“；”分隔，顺序与答案一一对应
{
  "type": "fill",
  "q": "时钟4点敲4下用6秒，那么12点敲12下用____秒。",
  "answer": "22",
  "explain": "4下有3个间隔，每间隔2秒；12下有11个间隔，共22秒。"
}

// 4) 主观题：没有自动判分，reference 是给 AI 批改用的参考要点
{
  "type": "subjective",
  "q": "桌上7只茶杯全部杯口朝上，每次只能翻动4只。能否经过若干次翻动使杯口全部朝下？说明理由。",
  "reference": "不能。每只杯口朝下需被翻奇数次，7只共需奇数总次数；每次翻4只，总次数恒为4的倍数，是偶数，矛盾。"
}
格式硬约束：选择题的 answer 必须是 "A"—"D" 之一，且 options 中确实存在对应字母；判断题必须是 true/false；填空题多个答案用全角分号；主观题必须有 reference，否则 AI 批改质量会明显下降。改完务必运行 npm test 与 node tools/verify-library.js。

C.5 校验与常见损坏

检查项命令通过标准
JSON 能否解析node -e "JSON.parse(require('fs').readFileSync('library/books/书ID.json','utf8')); console.log('ok')"输出 ok
全库结构与统计node tools/verify-library.js退出码 0，无缺章、无空书
应用自检npm test输出“自检通过：171 部书，版本 1.1.1”
目录与索引重建npm run index生成 catalog.json 与 search-index.json
习题答案自检node _work/tmp/check-exercises.js输出 ALL EXERCISE CHECKS PASSED（开发目录内）
单本书章节数node -e "const b=require('./library/books/书ID.json'); console.log(b.title, b.chapters.length)"与说明书书目表一致
书 ID 与文件名一致node -e "const f='书ID'; const b=require('./library/books/'+f+'.json'); if(b.id!==f) throw new Error('id 不一致'); console.log('ok')"输出 ok
重复 ID / 重复章节npm run index 的日志无“重复”警告，书数正确
最常见的三种损坏：① 用编辑器保存成了带 BOM 的 UTF-8（程序可读，但某些外部工具会报错）；② 复制粘贴时把英文引号换成了中文引号，导致 JSON 无法解析；③ 手改章节后没有重建索引，搜索仍指向旧章节。处理顺序永远是：修 JSON → npm test → npm run index → 刷新浏览器。

D.4 下载后先校验

# Linux / macOS / Termux / iSH：在附件所在目录执行
sha256sum -c SHA256SUMS.txt        # Linux / Termux / iSH
shasum -a 256 -c SHA256SUMS.txt    # macOS

# Windows CMD：逐个比对（输出里找 64 位十六进制）
certutil -hashfile wanjuan-ge-v1.1.1-windows.zip SHA256
findstr /I "wanjuan-ge-v1.1.1-windows.zip" SHA256SUMS.txt

# Windows PowerShell：自动比对
$file = 'wanjuan-ge-v1.1.1-windows.zip'
$actual = (Get-FileHash $file -Algorithm SHA256).Hash.ToLower()
$expected = (Select-String -Path SHA256SUMS.txt -Pattern $file).Line.Split(' ')[0]
if ($actual -eq $expected) { '校验通过' } else { '校验失败，请重新下载' }

校验失败通常不是文件损坏，而是下载被中断或代理返回了错误页面。重新下载即可；若多次失败，换用另一个平台的 Release 附件。

路径升级时如何处理原因
data/user.json必须保留并备份设置、API Key、进度、书签、笔记都在这里
data/translations/建议保留已翻译章节可继续命中缓存，省时省钱

release/、_work/不需要保留打包产物与开发中间文件，可由命令重建
